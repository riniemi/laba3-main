# Теория: структуры данных (ЛР3)

В этом документе собраны определения всех структур данных из лабораторной работы: что
представляет собой каждая структура, как она устроена и чем отличается от похожих структур.
Также приведены основные операции и их асимптотическая сложность O(...) для N элементов.
Проект существует в двух реализациях: C++ (`include/`, `src/`) и Go (`go/ds`). Логика у них
одинаковая.

## Общая архитектура

Все структуры наследуются от одного интерфейса и работают через него:

- **IStorable** (C++: `include/ds/istorable.hpp`, Go: `go/ds/storable.go`) — общий интерфейс
  структур, которые умеют сообщать свой тип и размер, отдавать данные, восстанавливать их и
  показывать себя в текстовом виде.
- **Фабрика** (C++: `include/ds/factory.hpp`, Go: `go/ds/factory.go`) — объект, который создает
  нужную структуру по ее букве типа. Клиентский код получает общий интерфейс и может работать
  с разными структурами одинаковым способом. Это пример полиморфизма.
- **Serializer** (C++: `include/ds/serializer.hpp`, Go: `go/ds/serializer.go`) — компонент для
  сохранения структуры в файл или поток и последующего восстановления. Он использует общий
  интерфейс `IStorable`, поэтому подходит для всех типов.

### Буквы типов

| Буква | Структура | Класс |
|:-----:|-----------|-------|
| M | динамический массив | `Array` |
| F | односвязный список | `SinglyList` |
| L | двусвязный список | `DoublyList` |
| S | стек | `Stack` |
| Q | очередь | `Queue` |
| T | полное двоичное дерево | `CompleteTree` |
| H | хеш-таблица | `HashTable` |

### Сводная таблица сложностей

| Операция | Структура | Сложность |
|----------|-----------|:---------:|
| добавление в конец | Array | O(1) амортизированно |
| вставка/удаление со сдвигом | Array | O(n) |
| доступ по индексу | Array | O(1) |
| pushHead / pushTail | SinglyList, DoublyList | O(1) |
| popHead | SinglyList, DoublyList | O(1) |
| popTail | SinglyList | O(n) |
| popTail | DoublyList | O(1) |
| поиск по значению | списки | O(n) |
| push / pop | Stack, Queue | O(1) |
| вставка / поиск / удаление | HashTable | O(1) в среднем |
| вставка в дерево | CompleteTree | O(n) |
| поиск в дереве | CompleteTree | O(n) |

## Массив (M)

**Массив** — это последовательность элементов одного типа, расположенных подряд в памяти.
В этой работе используется динамический массив строк: он хранит текущую длину `len` и
вместимость `cap`, то есть число элементов, для которых уже выделена память.

- **Доступ по индексу** — O(1): адрес элемента вычисляется как начало + индекс.
- **Вставка в конец** — O(1) амортизированно. Пока есть место, элемент дописывается сразу;
  когда места нет, массив расширяется (удвоение вместимости) и элементы копируются. Редкие
  дорогие копирования в среднем дают O(1) на одну вставку.
- **Вставка/удаление в середину** — O(n): все элементы справа нужно сдвинуть.

**Отличие от списка:** массив быстро обращается к элементу по индексу, но при вставке или удалении
в середине сдвигает соседние элементы. В списке элементы связаны указателями: к ним нельзя
перейти по индексу за O(1), зато вставка рядом с уже найденным узлом не требует сдвига остальных.

## Односвязный список (F)

**Односвязный список** — это последовательность узлов, в которой каждый узел хранит значение
и указатель `next` только на следующий узел. Список хранит указатели на первый узел (`head`)
и последний (`tail`), а также количество элементов `n`. Узлы могут находиться в разных местах
памяти, порядок задают указатели.

- **pushHead / pushTail** — O(1): вставка у головы и у хвоста по указателю.
- **popHead** — O(1); **popTail** — O(n): чтобы удалить последний узел, нужно дойти до предпоследнего
  (перед ним нельзя перескочить — нет указателя назад).
- **pushAfter / pushBefore / delValue / find / at** — O(n): сначала нужно найти место, а поиск идет
  от головы по цепочке `next`.

## Двусвязный список (L)

**Двусвязный список** — это последовательность узлов, каждый из которых хранит значение и два
указателя: `next` на следующий узел и `prev` на предыдущий. Список хранит `head`, `tail` и
количество элементов `n`.

- **popTail** — O(1): есть указатель на предпоследний узел, поэтому удаление с хвоста не требует
  обхода (главное отличие от односвязного списка).
- Операции по значению (поиск, вставка рядом с заданным) остаются O(n) из-за поиска.
- Список можно обходить от головы к хвосту и обратно: `items()` и `itemsReversed()`.

**Отличие от односвязного списка:** в односвязном узел знает только следующий элемент, поэтому
обход возможен только вперед, а удаление хвоста требует поиска предпоследнего узла за O(n).
В двусвязном есть ссылка назад: список можно обходить в обе стороны и удалять известный узел
за O(1), но каждый узел занимает память еще под один указатель. Поиск значения в обоих списках
все равно занимает O(n).

## Стек (S)

**Стек** — это структура данных, в которой добавление и удаление происходят с одного конца,
называемого вершиной. Он работает по принципу **LIFO** (последним пришел — первым вышел).
Например, после добавления `A`, затем `B`, первым удалится `B`.

В проекте стек построен поверх односвязного списка: вершина — это голова списка.
`push` добавляет элемент, `pop` снимает верхний; обе операции выполняются за O(1).
`dump()` возвращает элементы от низа к вершине.

**Отличие от очереди:** стек удаляет самый недавно добавленный элемент, очередь — самый давно
добавленный.

## Очередь (Q)

**Очередь** — это структура данных, в которую добавляют элементы с конца, а удаляют с начала.
Она работает по принципу **FIFO** (первым пришел — первым вышел). Например, после добавления
`A`, затем `B`, первым удалится `A`.

В проекте очередь построена поверх односвязного списка: начало очереди — голова, конец — хвост.
`push` добавляет в хвост, `pop` удаляет из головы; обе операции выполняются за O(1).
`dump()` возвращает элементы от начала к концу.

## Хеш-таблица (H)

**Хеш-таблица** — это структура для хранения пар «ключ — значение», которая использует хеш-функцию,
чтобы быстро вычислить место хранения ключа. В этой работе и ключ, и значение являются строками.
Таблица использует **открытую адресацию**: все пары хранятся в массиве ячеек, а при совпадении
адресов нескольких ключей (коллизии) для нового ключа ищется другая ячейка. Размер таблицы `N`
всегда простое число.

### Хеш-функции

Три независимые функции (файл `hashfn.hpp`):

- `hashDjb2` — основной хеш `h1 = djb2(ключ) mod N`;
- `hashFnv1a` — для шага двойного хеширования `h2 = 1 + fnv1a(ключ) mod (N - 1)`;
- `hashSdbm` — дополнительная хеш-функция строк.

Применяется **метод деления**: результат функции берется по модулю размера таблицы.

### Два метода разрешения коллизий

- **LINEAR** (линейное апробирование): i-я проба = `(h1 + i) mod N`, шаг всегда равен 1.
  Просто, но образуются «кластеры» занятых ячеек.
- **DOUBLE** (двойное хеширование): i-я проба = `(h1 + i * h2) mod N`, шаг зависит от ключа.
  Кластеров почти нет. То, что `N` простое, а шаг `h2` взаимно прост с `N`, гарантирует обход всех
  ячеек — ключ всегда найдется, если в таблице есть свободное место.

Поиск прекращается, когда встречается пустая ячейка: значит, цепочка проб закончилась и ключа нет.

### Надгробия и перестройка (рехеш)

Просто стереть ячейку нельзя — это оборвало бы цепочку проб других ключей. Поэтому удаление ставит
метку «удалено», **надгробие** (`\x01`), и таблица продолжает считать эту ячейку занятой для поиска.

Когда занятых ячеек (живых + надгробий) становится больше 70%, таблица пересобирается:

- если живых элементов больше половины — размер удваивается (точнее, берется следующее простое число);
- иначе размер сохраняется, а надгробия просто убираются (ключи раскладываются заново).

При перестройке все ключи хешируются заново.

## Полное двоичное дерево (T)

**Полное двоичное дерево** — это дерево, где у каждого узла не больше двух детей, все уровни,
кроме, возможно, последнего, заполнены полностью, а последний заполняется слева направо без
пропусков. В этой работе дерево хранит целые числа, в том числе отрицательные, например `-7`.

**Это не дерево поиска:** для дерева поиска значения в левой и правой ветвях подчиняются
правилу порядка, а в данном полном дереве такого правила нет. Поэтому поиск значения здесь
занимает O(n), хотя форма дерева остается полной.

- **Вставка** — O(n): новый узел кладется на **первое свободное место при обходе в ширину** (BFS).
  Чтобы его найти, иногда приходится пройти почти все дерево.
- **Поиск** — O(n): дерево не является деревом поиска (не упорядочено), поэтому проверяются все узлы.
- **Обходы**: `PREORDER` (прямой), `INORDER` (симметричный), `POSTORDER` (обратный), `BFS` (в ширину).
- **isComplete** — O(n): проверка полноты.

При сохранении дерево записывается прямым обходом с символом `#` на месте отсутствующих узлов,
поэтому в файле можно записать и **неполное** дерево.

## Сериализация

**Сериализация** — это преобразование структуры данных в последовательность байтов или текста,
которую можно сохранить, передать и позже восстановить. В проекте она работает с любой
структурой через `IStorable`. Поддерживаются два формата:

- **Текстовый** — одна строка `"<тип> <элемент> <элемент> ..."`, элементы с пробелами берутся в
  кавычки. Читается человеком. Пример: `S 1 2 "hello world"`.
- **Бинарный** — 4 байта сигнатуры `DSB1`, 1 байт типа, `uint32` число элементов, дальше для каждого
  элемента `uint32` длина и сами байты. Числа в порядке little-endian, поэтому файл читается
  одинаково на любой машине.

Общий принцип: чтобы сохранить, достаточно получить `dump()`; чтобы прочитать — создать пустую
структуру фабрикой и вызвать `load()`.

## Разбор чисел и индексов

- Индекс (`toIndex`) — неотрицательное целое, не длиннее 9 цифр.
- Число для дерева (`isInteger` / `normInt`) — целое со знаком, не длиннее 18 цифр; `"-007"`
  приводится к `"-7"`. Всё, что не подходит, вызывает ошибку.
