# Как это всё запускается

Все команды выполняются из папки `laba3-main` (корень проекта, там где лежит `Makefile`).
Проект состоит из C++-части (библиотека, тесты, бенчмарк) и Go-части (`go/`). У C++ нет отдельной
программы с меню — это библиотека, которую проверяют тестами и измеряют бенчмарком. Демонстрация
есть в Go (`go/cmd/demo`).

## Что должно быть установлено

- **C++:** компилятор `g++` (с поддержкой C++17), утилита `make`.
- **Фреймворки для тестов C++:** GoogleTest, Catch2 и Boost.Test. Нужны только для `make cpp-test`.
  Если каких-то нет — сама библиотека и бенчмарк все равно собираются. Установка (Arch/Manjaro):
  `sudo pacman -S gtest catch2 boost`.
- **Для покрытия C++:** `gcov` (идёт в комплекте с `g++`) и `gcovr` — только для `make cpp-cover`.
  Установка: `sudo pacman -S gcovr`.
- **Go:** версия 1.21 или новее, команда `go` в PATH. Установка (Arch/Manjaro):
  `sudo pacman -S go`, проверка: `go version`. Без установленного Go команды `make tidy`,
  `make test` и другие Go-цели не заработают (будет `go: Нет такого файла или каталога`).
- **Для бенчмарков Go:** `python3` (обработка таблицы).
- **Для линтеров Go:** `staticcheck` и `golangci-lint`.
- Для просмотра HTML-отчета покрытия — любая программа просмотра (например, `xdg-open`).

## Быстрый старт

Собрать и проверить C++:

```bash
make cpp          # собрать библиотеку
make cpp-test     # прогнать тесты (нужны gtest, catch2, boost)
make cpp-bench    # прогнать бенчмарк
```

Проверить Go:

```bash
cd go
make tidy         # один раз: скачать зависимости и создать go.sum
make test         # тесты с покрытием
```

## C++: цели Makefile

Все команды запускаются из корня `laba3-main`.

| Команда | Что делает |
|---------|-----------|
| `make cpp` | Собирает библиотеку в `build/libds.a` |
| `make cpp-test` | Собирает и запускает тесты на всех трех фреймворках |
| `make cpp-test-gtest` | Только тесты GoogleTest |
| `make cpp-test-catch2` | Только тесты Catch2 |
| `make cpp-test-boost` | Только тесты Boost.Test |
| `make cpp-bench` | Собирает и запускает бенчмарк |
| `make cpp-cover` | Покрытие всеми тремя наборами тестов + HTML-отчёт `coverage_cpp.html` (нужен `gcovr`) |
| `make cpp-lint` | Проверяет компиляцию: любое предупреждение — ошибка |
| `make clean` | Удаляет папку сборки `build/` и чистит Go |

Результаты сборки кладутся в папку `build/` (она не хранится в репозитории).
`make cpp-cover` проверяет общий порог не менее 85% по строкам, функциям и ветвлениям.
Для ветвлений gcovr исключает недостижимые переходы и служебные переходы обработки исключений,
сгенерированные компилятором. Дополнительно каждый файл `src/*.cpp` должен иметь минимум
85% покрытия по строкам и функциям.

### Как собрать вручную (без make)

```bash
# библиотека и пример теста gtest
g++ -std=c++17 -Iinclude -Itests \
    tests/test_gtest.cpp src/*.cpp \
    -lgtest -lgtest_main -pthread -o test_gtest
./test_gtest

# бенчмарк
g++ -std=c++17 -Iinclude bench/benchmark.cpp src/*.cpp -o benchmark
./benchmark
```

Флаги: `-Iinclude` — где искать заголовки проекта, `-Itests` — где лежит `test_utils.hpp`.

### Что печатает бенчмарк

Таблица вида «операция — теория — время (нс) для N = 1000, 4000, 16000», например:

```
операция                           теория        1000         4000        16000
Array::push (в конец)              O(1)            ...
Array::insert (в начало)           O(n)            ...
```

По ней видно асимптотику: у O(1) время почти не меняется с ростом N, у O(n) растет пропорционально N.

## Go: цели Makefile

Все команды из папки `go`.

| Команда | Что делает |
|---------|-----------|
| `make tidy` | Скачивает зависимости (testify) и создает `go.sum` |
| `make fmt` | Форматирует код через `gofmt` |
| `make test` | Тесты кратко, с процентом покрытия |
| `make test-v` | Тесты подробно (по каждому тесту) |
| `make cover` | Покрытие + функция за функцией + HTML-отчет `coverage.html` |
| `make bench` | Бенчмарки, результат сразу в виде таблицы (`tools/benchtable.py`) |
| `make lint` | Проверки: gofmt, go vet, staticcheck, golangci-lint |
| `make demo` | Запускает демонстрацию `go/cmd/demo` |
| `make clean` | Удаляет файлы покрытия, бенчмарков и демо |

### Как запустить вручную (без make)

```bash
go test ./...        # все тесты
go test -v ./ds      # тесты пакета ds подробно
go run ./cmd/demo    # демонстрация
```

### Из корня проекта

Корневой `Makefile` умеет вызывать Go-цели, не заходя в `go/`. Для `tidy` и `fmt` есть
короткие имена (без префикса `go-`):

```bash
make tidy         # = make go-tidy: скачать зависимости (testify), создать go.sum
make fmt          # = make go-fmt:  форматирование gofmt
make go-test
make go-cover
make go-bench
make go-lint
```

Перед Go-целями установи Go (`sudo pacman -S go`), иначе будет ошибка
`go: Нет такого файла или каталога`.

## Полный цикл проверки одной командой

```bash
make cpp && make cpp-test && make cpp-bench
```

```bash
cd go && make tidy && make test && make bench
```

## Частые вопросы

- **`make cpp` пишет «Цель «cpp» не требует выполнения команд»** — это не ошибка: библиотека
  `build/libds.a` уже собрана и новее исходников. Пересобрать принудительно: `make -B cpp`.
- **`make cpp-test` падает на сборке** — скорее всего не установлен один из фреймворков
  (GoogleTest, Catch2 или Boost.Test). Установи их: `sudo pacman -S gtest catch2 boost`.
  Либо запускай тесты по одному: `make cpp-test-gtest`.
- **`make cpp-cover` не находит `gcovr`** — установи его: `sudo pacman -S gcovr`.
- **`make test` в Go просит зависимости** — выполните один раз `make tidy` (нужен интернет).
- **`make go-lint` не находит `staticcheck` или `golangci-lint`** — эти инструменты ставятся отдельно
  и в стандартную поставку Go не входят.
- **`go.sum` отсутствует** — он появляется после `make tidy`; до этого команды Go из репозитория
  могут ругаться на зависимости.
